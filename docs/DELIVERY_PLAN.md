Bounded workstreams: lifecycle backend, frontend integration, challenger/domain pipeline; principal agent owns authoritative records, refresh orchestration, packaging and final verification. Implementation agents exchange typed artifact contracts before UI integration. Frozen scientific files and prior evidence are protected by pre/post hashes. Independent formula checks and adversarial tests challenge implementation assumptions.

Completion is assessed per capability: a documented interface is not a working source adapter; a source candidate is not permission for redistribution; synthetic metrics are not production evaluation; a trained challenger is not an approved model. The final HANDOFF and RELEASE_GATES must list these distinctions and the next actual dependency rather than restating the full product wishlist.

## Delivered increment and actual next dependencies

Phases 1–2 are implemented locally: locked requirements, exact current source, actual-time refresh, 13 current forecasts and missing-data guards. Phases 4–5 have working immutable catalog, source-proof reconciliation, all-version/final-per-game metrics, deterministic investigation and verified local evidence bundles. Six primary React views and historical deep links consume these real artifacts. Prospective scored count is zero until a recorded game finishes; this is a data state, not a fabricated demonstration score.

Phase 3 is partial by domain: seven schedule domains are trained/evaluated in a separate fixed challenger (travel remains rest/byes only). Three actual current-source adapters provide context-only injury, QB depth-chart and basic team-stat annotations. They do not establish historical feature vintages or trained contribution. Confirmed starters, individual QB performance, weather, news and travel distance remain unavailable. Current2026 prior strength is blocked by the 2025 holdout boundary; do not relax it.

Phase 6 has a reproducible fixed-config challenger, chronological calibration/backtests, ablations, uncertainty, registry and promotion/rollback criteria. Promotion is NO-GO: failed season calibration threshold, absent prospective full-season shadow evidence, unavailable live prior-strength input and historical vintages, and no owner approval. The app shows both positive and failing evidence.

Phase 7 verification is recorded in EXECUTION_VALIDATION.json. The next owner review is local acceptance of this increment. Hosted persistence/restoration, long-season static history partitioning, source/license and account billing decisions, runner validation and explicit scheduling/publication approvals are prerequisites to G3. They are not silently enabled by a successful local build. Context source collection remains explicit and independent; optional LLM research and automated promotion are not implemented.
