## Eligibility, state and prediction-time availability
Assess regular-season games with season label 2024 or 2025, including January games belonging to those seasons. Preserve existing rules: unique nonmissing IDs; valid integer season/week (1–18), identity/date fields and nonnegative finite integer scores; distinct teams. Binary evaluation uses only games with both scores present and unequal. Exclude ties from targets, but count completed ties as half a win in later history. Incomplete games never update state. Reject invalid inputs; do not silently drop malformed rows. Report source, complete, tied, incomplete, eligible, scored and unavailable counts by season and pooled, with reasons for every exclusion. Missing/nonfinite required predictor means unavailable, never an invented probability. If any eligible game is unavailable, stop comparative scoring and report the coverage failure before owner review; do not choose a favorable subset.

State resets each season. For each team and game, use only completed games in that same season on dates strictly earlier than 00:00 America/New_York on game date. All games on a date read the same earlier-day state and update only after the date's features are produced. Earlier 2024/2025 outcomes may enter later features only through this deterministic chronological replay after execution is authorized; coefficients stay fixed. No same-day/current/future results enter their own features. Corrected historical schedules do not prove vintage publication availability; retain that limitation.

For each team with n earlier completed games, wins w (ties half), ordered scoring margins m and last completed date d: smooth_win = (w+2)/(n+4); margin = sum(m)/(n+4); recent_margin = sum(last five m)/(min(n,5)+2); rest = min(14, calendar days since d), or 7 with no history. ## Metrics, pooling and uncertainty
Report the candidate and both constant baselines separately for 2024, separately for 2025, and pooled across all eligible games (game-weighted, not an equal average of season scores). Primary metric: Brier score. Secondary metrics: log loss using the frozen logistic probabilities and numeric clipping only at float64 machine epsilon if needed; accuracy at p >= 0.5; fixed ten equal-width probability bins with count, mean prediction and observed home-win rate. Assign p=1 to the last bin. Publish all bins, including zero counts with null means. Also report paired per-game Brier differences against each baseline. Use unrounded values for calculations; rounding is display only.

Use paired season-week blocks, with block key (season, week), never week number alone. Keep all observations and all three predictions together when resampling a block. For each per-season estimate, uniformly draw that season's observed week blocks with replacement, drawing the same number of blocks as observed. For the pooled estimate, stratify by season: draw the original number of observed blocks within each season independently, concatenate selected rows from both seasons, and compute game-weighted metrics/differences on the combined rows. Do not sample games independently or pool equal-numbered weeks from different seasons into one block.

Use numpy.random.default_rng(42), 2,000 replicates, seasons/weeks/game IDs in ascending canonical order; reset RNG to 42 separately for the 2024 report, 2025 report and pooled report. Reuse each report's block draws for all models and paired differences. Report 2.5% and 97.5% empirical quantiles with NumPy's linear method for Brier, log loss, accuracy and each paired Brier difference. Treat intervals as descriptive: a small number of blocks, temporal dependence, validation selection and partial exposure limit inference. Do not interpret calibration plots or a zero-excluding interval as proof of generalizable skill.
